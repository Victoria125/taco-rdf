# Is TACO's value the same quantity as NEVO's?

Generated by `python scripts/nutrient_definitions.py` from Fuseki's `nicefood` dataset and TACO's printed table (4th edition, PDF), and checked by `python verification/nutrient_definitions_check.py`. NEVO appears only as counts and shares, never as a value.

In TACO's NICE-Food export, 41 TACO nutrients take a NEVO nutrient code (`data/alignment/taco_nevo_nutrients.csv`). A shared code says the two tables measure the same thing. For each, this compares what TACO declares, its INFOODS tagname and method, with tests on both tables' data.

## Tests on the data

Each test is run on every food with the values it needs; it holds for a table when it holds for 95% of its foods.

| Test | NEVO | TACO |
| --- | --- | --- |
| carbohydrate: available carbohydrate is the sum of sugars and starch | 1,646 of 1,672 (98%) | 0 of 582 (0%) |
| energy kcal: energy follows the general EU factors | 1,664 of 1,673 (99%) | 196 of 548 (36%) |
| energy kJ: energy follows the general EU factors | 1,664 of 1,673 (99%) | 181 of 548 (33%) |
| protein: protein is nitrogen times 6.25 | 18 of 347 (5%) | not testable |
| vitamin A: retinol equivalents count carotenoids twice as much as retinol activity equivalents | 589 of 592 (99%) | 102 of 102 (100%) |
| fatty acids: saturated fatty acids are at most the fat, so per 100 g of food | 1,673 of 1,673 (100%) | 414 of 415 (100%) |

NEVO's protein-to-nitrogen ratio takes 132 different values (median 6.29), so NEVO uses a factor per food, as TACO uses Jones's factors (TACO, PDF page 16). TACO's carbohydrate is by difference and includes fibre (page 16), so TACO has no sum of sugars and starch: the export's available carbohydrate is carbohydrate minus fibre. TACO's energy uses Atwater's specific coefficients (page 16), NEVO's the general EU factors.

## What this means for the shared code

- **Calculated another way** (carbohydrate, energy): the code is shared, the number is not comparable as it is. TACO's value keeps how it was calculated (`prov:wasDerivedFrom` and a description for available carbohydrate), but a query by the code does not see it.
- **NEVO's values are under another code** (sodium): NICE-Food's graph has 1,672 NEVO sodium values under `nevonut:nan`, labelled Sodium. Its notebook (`nevo_processing.ipynb`, rivm-syso/nicekg_processing) reads NEVO's file with `pandas.read_csv`, which reads the code `NA` as a missing value, and writes the IRI from `str(...)`, which gives `nan`. A query for sodium finds TACO under `nevonut:NA` and NEVO under `nevonut:nan`, never both. Reading the file with `keep_default_na=False` would keep `NA`.
- **Another unit** (tryptophan): TACO gives g, NEVO mg. Each measure keeps its unit, so a query must convert before comparing.
- **To confirm with NEVO's method**: the name, unit and INFOODS meaning agree, but NEVO's method is not in this repository (fat extraction, fibre method, the vitamins' methods).
